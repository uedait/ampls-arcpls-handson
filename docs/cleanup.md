# 後片付け・切り戻し

[README](../README.md) / [事前確認](prerequisites.md)

## 原則

後片付けを実施する前に、削除対象の完全なリソース ID、所有者、残すリソース、ログの保管期間、影響を提示して承認を得てください。本資料の閲覧や構築承認は削除の承認を意味しません。

既存 DNS、Firewall、VNet、Resolver、VM、既存 LAW / AMPLS を削除しません。作業用 RG に既存リソースがないことを確認できなければ、RG の一括削除を使用しません。自動削除スクリプトは用意していません。

## 1. 試験中に問題が起きた場合

1. 試験を止め、ネットワーク / DNS / 監視の担当者に対象と時刻を連絡します。
2. Proxy の一時解除試験中なら、記録した Arc の `proxy.url` / `proxy.bypass` を復元し、チェックが成功することを確認します。
3. 今回追加した対象限定の直接公開通信 Deny 等を、記録した元の値に戻します。関係のない NSG / Firewall ルールは変更しません。
4. DNS の変更が原因なら、今回**新規作成した**条件付きフォワーダーだけを削除します。既存の転送先を承認の上で変更した場合は、元の転送先、タイムアウト、AD 複製範囲を復元します。
5. 作業前後の DNS 応答と既存業務の疎通を担当者が確認します。共有 DNS サーバー全体のキャッシュ消去・再起動を一律に実施しません。専用対象の必要なキャッシュだけを、担当者の判断で更新します。
6. AMPLS / DNS zone の変更で既存監視に影響した場合は、変更記録に従い link / record / mode を復元します。既存 AMPLS の関連付けをまとめて削除しません。

問題を解消できなければ、既存業務の復旧を優先してハンズオンを中断します。

## 2. 検証対象の収集設定を外す

1. 検証結果を安全な保管先に保存し、LAW のデータを残すか削除するか決めます。削除後のデータは再取得できません。
2. Portal の今回の DCR から、今回追加した Azure VM / Arc machine の関連付けを外します。元から存在する関連付けを外しません。
3. DCE の「リソース」から今回の設定取得先の関連付けを外します。作業前から DCE があった対象は、事前記録に従い元へ復元します。
4. 今回だけの AMA で、ほかの DCR / 管理機能が使っていないことを確認できた場合に限り、対象の「拡張機能」から `AzureMonitorWindowsAgent` を削除します。
5. Azure VM のマネージド ID が他用途で使われていないか確認します。既存 ID を無効にしません。

## 3. 今回の Arc 登録を解除する

1. AMA 等の拡張機能を除去してよいか確認します。Arc の解除は、管理機能、ポリシー、ESU 等にも影響し得ます。既存 Arc へ適用しません。
2. 対象サーバーで、正しいテナントと machine であることを `azcmagent show` で確認します。
3. 必要な Entra ID / ARM の Proxy 到達性を残したまま、公式の[Arc Agent 管理手順](https://learn.microsoft.com/azure/azure-arc/servers/manage-agent)に従い `azcmagent disconnect` で今回の登録を解除します。手動認証の案内に従い、サインイン情報を記録しません。
4. Portal で対象の Arc machine と PLS 関連付けの解除を確認します。登録解除に失敗した場合は、Azure 側だけ削除して正常完了とせず、サーバー側の状態も確認します。
5. 今回導入した Agent を残す必要がなければ「アプリと機能」から Azure Connected Machine Agent をアンインストールします。手順と再起動要否を確認します。
6. 検証用の Event Source `AmplsArcHandson` を取り除く場合は、他用途で使っていないことを確認して `Remove-EventLog -Source AmplsArcHandson` を使用します。Application ログ自体は削除しません。

## 4. Azure 側の検証リソースを削除する

Portal で対象 ID と依存関係を確認して、個別に実施します。

1. 今回だけの DCR を削除します。
2. AMPLS から、今回追加した LAW / DCE の scoped resource 関連付けを外します。共有 scope を残す場合、ほかの関連付けは維持します。
3. 今回だけの AMPLS PE / Arc PE を削除し、DNS zone group とレコードへの影響を確認します。
4. 関連 machine が残っていない今回だけの Arc PLS、参照先を外した今回だけの AMPLS を削除します。
5. 他で使っていない今回の DCE / LAW を削除します。LAW を残す場合は、不要な診断ログ送信設定と課金対象も確認します。
6. 今回作成し、他の PE / VNet が使っていない zone / VNet link / レコードのみを削除します。Windows DNS の条件付きフォワーダーも、残す閉域サービスがないか確認して戻します。
7. 今回だけの Firewall 診断設定、Application rule、Explicit Proxy の変更を戻します。共有 Policy 全体を削除・無効化しません。

AMPLS に関連付けた LAW / DCE は、関連付けを残したまま削除できません。削除失敗時に別の共有リソースを削除して進めないでください。

## 5. 任意ラボの終了

①で作った専用 RG の全リソースを棚卸しし、②③の残存リソースと所有者も確認します。専用であることと一括削除の承認が確認できた場合のみ、Portal からその RG を削除します。管理接続、ディスク、Firewall、Resolver、PE、Public IP 等の残存を確認してください。

VM を停止しただけでは、Firewall / Resolver / ディスク等の課金は終了しません。予算期限内に削除が完了したか、担当者が確認します。顧客の既存環境にこの RG 一括削除を適用しません。
